SAGA ORCHESTRATION ARCHITECTURE

Lược Đồ SAGA ORCHESTRATION (Điều Phối Tập Trung)

Borrow Service đóng vai trò là Orchestrator điều phối các Worker Services qua Command & Reply Channels

💥 Kịch Bản Bù Trừ: Orchestrator phát lệnh Hoàn Kho (+1) & Rollback Phiếu Mượn
Saga Orchestrator Compensation 
sequenceDiagram
    autonumber
    actor Client as 👤 Client (Frontend)
    participant Orch as 🧭 Borrow Service
[Saga Orchestrator]
    participant Kafka as ⚡ Apache Kafka
    participant BookWorker as 📚 Book Service
[Inventory Worker]
    participant UserWorker as 👤 User Service
[Validator Worker]

    Client->>Orch: POST /api/borrows (userId: 5, bookId: "B001")
    
    rect rgb(20, 35, 55)
        note over Orch: GIAI ĐOẠN 1: ORCHESTRATOR LƯU STATE BAN ĐẦU
        Orch->>Orch: 1. Tạo Saga Instance (sagaId)
2. Tạo BorrowRecord (status: IN_PROGRESS)
3. Tăng user.borrowed_count + 1
        Orch-->>Client: HTTP 202 Accepted { sagaId, status: "IN_PROGRESS" }
    end

    rect rgb(20, 45, 35)
        note over Orch,BookWorker: GIAI ĐOẠN 2: ĐIỀU PHỐI TRỪ KHO SÁCH
        Orch->>Kafka: Phát Command: `book.cmd.reserve` (sagaId, bookId, qty: 1)
        Kafka->>BookWorker: Consume `book.cmd.reserve`
        BookWorker->>BookWorker: Local Tx: Stock = Stock - 1 (Commit DB Book)
        BookWorker-->>Kafka: Bắn Reply: `book.reply.reserved` (status: SUCCESS)
        Kafka->>Orch: Consume Reply -> State = BOOK_RESERVED
    end

    rect rgb(50, 25, 30)
        note over Orch,UserWorker: GIAI ĐOẠN 3: ĐIỀU PHỐI CHECK QUÁ HẠN
        Orch->>Kafka: Phát Command: `user.cmd.check-overdue` (sagaId, userId: 5)
        Kafka->>UserWorker: Consume `user.cmd.check-overdue`
        UserWorker->>UserWorker: Kiểm tra: User có 1 sách quá hạn!
        UserWorker-->>Kafka: Bắn Reply: `user.reply.checked` (isEligible: FALSE)
        Kafka->>Orch: Consume Reply -> Orchestrator phát hiện FAIL ở Bước 3!
    end

    rect rgb(65, 20, 25)
        note over Orch,BookWorker: BÙ TRỪ 1: ORCHESTRATOR PHÁT LỆNH HOÀN KHO
        Orch->>Orch: State = COMPENSATING
        Orch->>Kafka: Phát Command Bù Trừ: `book.cmd.compensate` (sagaId, bookId, qty: 1)
        Kafka->>BookWorker: Consume `book.cmd.compensate`
        BookWorker->>BookWorker: Local Tx Bù trừ: Stock = Stock + 1 (Rollback DB Book)
        BookWorker-->>Kafka: Bắn Reply: `book.reply.compensated` (status: SUCCESS)
        Kafka->>Orch: Consume Reply -> Đã hoàn kho thành công
    end

    rect rgb(55, 25, 45)
        note over Orch: BÙ TRỪ 2: ORCHESTRATOR ROLLBACK PHIẾU MƯỢN CỦA USER
        Orch->>Orch: Cập nhật BorrowRecord: status = REJECTED_OVERDUE
Giảm lại user.borrowed_count - 1
    end

    Orch-)Client: Gửi WebSocket/SSE: "Mượn thất bại do tài khoản còn sách quá hạn (Đã hoàn kho & hủy phiếu)."
🧭 Ưu điểm của Saga Orchestration:
  • Quyền điều phối tập trung nằm hoàn toàn ở Borrow-Service.
  • Book-Service và User-Service là các Worker thụ động, chỉ nhận Command và trả về Reply, hoàn toàn độc lập với nhau.
  • Dễ dàng mở rộng thêm bước (ví dụ: thêm Notification Service, Point Service) mà chỉ cần sửa Orchestrator, không ảnh hưởng các worker khác.

Thành công 
sequenceDiagram
    autonumber
    actor Client as 👤 Client
    participant Orch as 🧭 Borrow Service (Orchestrator)
    participant Kafka as ⚡ Apache Kafka
    participant BookWorker as 📚 Book Service (Worker)
    participant UserWorker as 👤 User Service (Worker)

    Client->>Orch: POST /api/borrows
    Orch->>Orch: 1. Lưu BorrowRecord (IN_PROGRESS) & borrowed_count + 1
    Orch-->>Client: HTTP 202 Accepted

    note over Orch,BookWorker: 2. Điều phối trừ kho
    Orch->>Kafka: Command `book.cmd.reserve`
    Kafka->>BookWorker: Stock = Stock - 1
    BookWorker-->>Kafka: Reply `book.reply.reserved` (SUCCESS)
    Kafka->>Orch: State -> BOOK_RESERVED

    note over Orch,UserWorker: 3. Điều phối check quá hạn
    Orch->>Kafka: Command `user.cmd.check-overdue`
    Kafka->>UserWorker: Validate: Không nợ quá hạn
    UserWorker-->>Kafka: Reply `user.reply.checked` (ELIGIBLE)
    Kafka->>Orch: State -> USER_ELIGIBLE

    note over Orch: 4. Chốt thành công
    Orch->>Orch: Cập nhật BorrowRecord: status = APPROVED
State = COMPLETED
    Orch-)Client: WebSocket: "Mượn sách thành công!"

Saga FSM 
stateDiagram-v2
    [*] --> IN_PROGRESS: 1. Tạo BorrowRecord (IN_PROGRESS)
    
    IN_PROGRESS --> RESERVING_BOOK: Phát `book.cmd.reserve`
    
    RESERVING_BOOK --> ROLLBACK_RECORD_ONLY: Hết sách trong kho
    ROLLBACK_RECORD_ONLY --> REJECTED_OUT_OF_STOCK: Rollback BorrowRecord & borrowed_count (-1)
    REJECTED_OUT_OF_STOCK --> [*]

    RESERVING_BOOK --> CHECKING_USER: Kho trừ thành công (-1) -> Phát `user.cmd.check-overdue`
    
    CHECKING_USER --> APPROVED: User không nợ quá hạn
    APPROVED --> [*]: Mượn thành công!

    CHECKING_USER --> COMPENSATING_BOOK: User nợ sách quá hạn -> Phát `book.cmd.compensate`
    
    COMPENSATING_BOOK --> COMPENSATING_BORROW_RECORD: Nhận `book.reply.compensated`
    COMPENSATING_BORROW_RECORD --> REJECTED_OVERDUE: Rollback BorrowRecord & borrowed_count (-1)
    REJECTED_OVERDUE --> [*]: Rollback hoàn tất
